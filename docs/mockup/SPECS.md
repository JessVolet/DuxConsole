# DuxConsole visual prototype specifications

Status: implementation available. Visual acceptance remains open where the roadmap records deviations. Reference: user-provided `MOCKUPWEB.mp4`, 1920 × 1080, 112 seconds. SHA-256: `b0f84b2712d1f65c44c3755f53b53091441e2311206c51173d1c73e8c26ddad7`. Timestamps refer to elapsed file time. The reference defines layout and visual states. Inputs and behavior below are design contracts derived from DuxConsole, since the recording does not establish every input binding.

## Scope

Build an opt-in, fixture-driven QML prototype inside DuxConsole that follows the reference's composition, density, hierarchy, card geometry and motion closely. Use original or approved assets and synthetic profiles, cover art, backdrop, media and game names. Match the visual role and framing of reference imagery. A fixture may play bundled sample media. Recording, power, app launch, Discord, system audio and controller profile actions affect demo state only. The existing web prototype is the reference and a secondary reuse target. Connecting the new screens to real capture, audio, social and system services is outside this phase.

## Module contracts

| ID | Module | Inputs and ownership | Outputs, states and acceptance |
| --- | --- | --- | --- |
| M01 | Shell and chrome | App supplies slide ID, overlay state, status and contextual hints. Shell positions backdrop, brand, centered five-tab navigation, right status, three circular capture shortcuts (screenshot, record and replay), and bottom hints. | Emits semantic navigation requests. At 00:08, match the three independent top groups, dim backdrop and compact footer. At 01:51, show the backdrop with the dashboard dismissed. Status, capture indicators and notices only mount once. |
| M02 | Design tokens and primitives | Theme, locale, glyph and motion providers supply roles, strings and resolved glyphs. Primitives receive visual state, content and accessible labels. | Surface, pill, icon button, glyph, meter, progress and focus treatment are reusable. Match light chrome and lavender accents over dark translucent content. Paint opacity on the fill and keep text/icons opaque. Selected card draws its own thicker border. |
| M03 | Focus, actions and layers | One controller owns active layer, active zone, remembered item and action dispatch. Native input managers translate configured inputs. The web reference uses browser adapters. | D-pad changes zones. LT/RT changes items in the active zone. LB/RB changes slides on dashboard. Select expands capable zones. Refuse pops and restores the exact zone and item by ID, with a deterministic surviving neighbor if it disappeared. Underlying layers are inert for keyboard, pointer and assistive tech. |
| M04 | Carousel | Receives ordered stable IDs, selected ID, visible budget, layout preset and custom card renderer. Parent owns selection. | Emits selection and activation intents. Home reference shows one leading and up to three trailing neighbors at desktop, plus the selected card. Other presets use the measured reference. Clamp the rendered window to actual count and available space. With 0 show an empty state, with 1 disable cycling, with 2–6 rotate unique IDs as a queue when wrapping, and with 7+ loop using a bounded window. Departing cards fade at the edge before recycling, incoming cards fade in on their own edge. Maintain gaps including the skew and focused border. |
| M05 | Home | Receives active session independently of selected window, window list, current track, social status and achievement digest. | At 00:08 and 00:28 match hero at left, large title up to two lines, compact metadata and actions, lower window strip and lower-right media/social stack and the light achievement digest below the top-right capture shortcuts. Changing selected window updates its card and options while the session hero remains stable. Focus/continue simulates return to the session. Expose a readable icon or initials when no thumbnail exists. |
| M06 | Audio | Receives output, microphone, list of app channel IDs, selected channel and media state. Mock provider owns volume and mute. | At 00:40–00:56 show gauge on the left, mixer on the right and bottom media/output/input cards. Expanded media panel keeps position and play state. Handle missing devices and no active media. Clamp volume to 0–100 and expose value to assistive technology. |
| M07 | Capture | Receives gallery, preview selection, recording state, replay availability and options. | At 01:01 show actions at left, preview at right and lower gallery. Compare the expanded viewer and strip in the 01:05–01:08 sequence, including its image and video variants. At 00:20 compare recording options and completion toast. Demo capture adds a fixture item. Record toggles the indicator, replay depends on the buffer option. Empty gallery and failed media have explicit states. |
| M08 | Launcher | Receives catalog, filter ID and selected entry ID. | At 01:12–01:15 compare the selection hero, lower Library carousel and filter pill. Selection updates hero details. | M10 | Orbit wheels and previews | Receives wheel side, category, command ID and a registry of command metadata and handlers. | Match wheels anchored to upper corners and preview panel opposite the wheel. ## Fidelity and acceptance

- Review paired reference/render stills at 1920 × 1080 for every scene in M01 and M05–M10. Pause the reference at the specified state, record the exact frame, and annotate bounding boxes for hero, chrome, card strip, preview and footer where applicable. At desktop, use a 2% viewport tolerance for principal positions and sizes and compare text wrapping, hierarchy, palette and clipping by eye. Exclude fixture artwork and capture-tool cursor/badges from the geometry comparison.
- Compare a recording of selection, wrap, fade, overlay open and focus restoration against the corresponding reference sequences. Measure entrance/exit timing and direction before choosing motion tokens. With animation disabled, commit the final state immediately. A resize, rapid repeated input or model update must leave a single valid selection.
- Verify the native prototype at 1920 × 1080, 1600 × 900 and 1280 × 720. On narrower screens allow flow/stacking and fewer visible cards using the same components. Keep side effects, focus visibility and text readability intact. Check ES/EN, keyboard, pointer and a connected supported gamepad when available. The QML input contract takes precedence over any D-pad item cycling observed in the web source.
- Compare prototype fixtures with counts 0, 1, 2, 4, 6 and 7+, long labels, missing images, missing gamepad and dialog-from-wheel. Track observed deviations with a frame or reproduction and an explicit disposition before calling parity complete.
